## Hard Stop

### 1. `conjunction-assessment` still depends on OrbPro plugin-sdk generated headers

Build command:

```bash
cd packages/conjunction-assessment && bash build.sh
```

Current failure:

```text
fatal error: '../../../../plugin-sdk/include/generated/PropagatorTrajectorySegments_generated.h' file not found
```

The missing header is not part of `space-data-module-sdk` `0.5.22`. The source
is hardcoded to an OrbPro-era plugin-sdk path:

- `packages/conjunction-assessment/src/cpp/src/resident_screening_index.cpp`

The matching headers currently exist only in the sibling OrbPro workspace:

- `../OrbPro/packages/space-data-module-sdk/orbpro-plugin-sdk/include/generated/PropagatorTrajectorySegments_generated.h`
- `../OrbPro/packages/space-data-module-sdk/orbpro-plugin-sdk/include/generated/StateVector_generated.h`

This is an external contract dependency, not a canonical SDK `0.5.22`
dependency.

## Why This Is The Stop Point

The repo now has a verified green path for the packages that are already
structured as SDN SDK modules, including the IPFS/licensing round-trip path.

The remaining blocked native packages are not just failing ordinary builds:
they still depend on OrbPro plugin-sdk generated schemas and/or OrbPro-specific
runtime assumptions that are outside the canonical `space-data-module-sdk`
`0.5.22` contract.

That means there are only two ways forward:

1. Vendor and preserve the old OrbPro plugin-sdk schema/runtime surface here,
   which would compile those packages but would still not make them canonical
   SDK `0.5.22` modules.
2. Rewrite those packages locally onto the canonical SDK command-surface and
   isomorphic artifact contract.

Because the current source proves a live dependency on an external OrbPro
plugin-sdk contract that is not part of `space-data-module-sdk` `0.5.22`, this
repo-only pass stops here per instruction.
