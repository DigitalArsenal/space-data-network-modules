## Implemented

- All eight ratified `rfmAxisType` values 25–32 work in source and target
  `RFMCoordinateSystem` records inside production `$FRM` `FRAME_ROTATION`
  and `STATE_TRANSFORM` requests.
- IERS1996 uses the ratified EOP double nutation corrections. The EOP table
  adapter reads, validates, and interpolates dPsi/dEpsilon alongside the
  existing fields. Missing corrections retain the SDS zero defaults.
- IERS2003 returns corrected true-of-date axes, using IAU2000A offsets.
  Separate 2000A/2006 correction sets preserve the observed pole and existing
  lane-02 EOP behavior. The mean-of-date FK5 selector remains unchanged.
- ENU/NED/SEZ use the existing named C++ helpers, with valid matching
  ground-site geometry. Wire VNC follows the ratified X=velocity, Z=normal
  ordering; RTN and LVLH derive from the existing RTN triad.
- Named orbital frames use the referenced object's origin, position, and
  velocity. Their central-force rotation rates include the distinct eccentric
  VNC rate and correct passive-rotation sign.
- Generated C++ headers consume published SDS 1.219.0. The module package and
  lockfile already pinned/resolved 1.219.0 on the requested base, so no further
  dependency edit was needed. FRM, RFM, and EOP headers were regenerated;
  FRM's generated bytes did not change.
- Rebuilt the SDK artifact, updated input/convention documentation, and added
  authoritative production-invoke tests plus an explicit three-runtime gate.
  The new runner checks child test counts to prevent inherited
  `NODE_TEST_CONTEXT` from falsely passing a skipped nested suite.

All production calculations remain C++. No schema was invented or edited.
No canonical checkout content or other lane directory was changed. No deploy
or merge is part of this branch. Build signing used only the SDK's public
synthetic development test fixture, not production credentials.

## Remaining scope and commit guard

No blocker remains for this selector follow-up. The documented provider
limits remain: Earth-only ground-site origins and geocentric object_state;
orbital rates assume central acceleration because FRM has no acceleration
field. Hosts must supply the declared root frame and epoch on object_state.
The new IERS values select TOD, not a different full BODY_FIXED Earth chain.
Full Herring prediction and binary-PCK lunar precision remain outside the
first pass and this follow-up. Historical generic OBJECT_REFERENCED behavior
was not changed; this lane implements the new named orbital selectors.
