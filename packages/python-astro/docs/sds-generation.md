# Reproducible Python FlatBuffer bindings

FFM (Full Force Model) is defined in [the FFM specification](../../../propagator/ffm/FFM.md).

The wheel vendors generated output from ratified SDS **1.265.0**, Git commit
`1b135309866cfa0ecf08248143c8ffbff5564b33` (package metadata
`1.265.0+1792874245672`). It does not require the stale PyPI SDS distribution.
The source is read using `git archive <commit> lib/py`; uncommitted generator
changes in the canonical checkout cannot alter the package.

`src/spacedatanetwork_astro/bindings.lock.json` records SHA-256 for **every file**
in that immutable `lib/py` tree, plus every vendored output and module-local
schema input. The full source manifest is itself hashed using sorted,
indented JSON with one trailing newline. Vendored families are PIV, TAB, OMM,
CAT, REC, RFM, CRD, MEM, OCM, ODR, TDM, TRH, CDM, CSM, ACW, EVL, PCE, EOP,
FRM, OEM, LMO, LMS, TIM, and NCD. Their generated imports determine the closure.
REC includes generated record-union members for the standards it can contain.

## Regenerate and verify

From the modules repository root, with its pinned npm dependencies installed:

```sh
python3 packages/python-astro/scripts/vendor_sds.py \
  --sds-repo /path/to/spacedatastandards.org --sds-only
python3 packages/python-astro/scripts/vendor_sds.py \
  --sds-repo /path/to/spacedatastandards.org --sds-only --check
PYTHONPATH=packages/python-astro/src python3 -m unittest discover \
  -s packages/python-astro/tests -p test_vendoring.py -v
```

Run regeneration after `prepare_artifacts.py`, because the binding lock also
records the distributed WASM hashes, module-declared SDS dependencies, and
available artifact build provenance. The SDS version selected for Python
bindings is the coordinator's 1.265.0 pin; older module-declared dependencies
are recorded transparently rather than rewritten.

`--sds-only` refreshes `sds/` and the lock's SDS, artifact and license
sections; `invoke/` and its lock section stay as committed. Without it the
module-local invoke bindings regenerate too, from the SDK and `flatc-wasm`
recorded in the lock (`FLATC_VERSION` in the script).

Bare generator imports such as `import CelestialFrameWrapper` become private
qualified imports retaining the original local alias. `from Type import Type`
is rewritten similarly. This is done with Python AST source positions, without
changing generated classes, fields, defaults, or wire layout. The distribution
does not insert top-level names into `sys.modules` or change `sys.path`.

| --- | --- | --- |

| SGP4 batch request | `propagator/sgp4/schemas/StateVector.fbs` | `.invoke.legacy.orbpro.propagator` |

| Access | ratified SDS ACW | `.sds.ACW` |

| Time and frames | ratified SDS TIM/FRM/RFM | `.sds.TIM`, `.sds.FRM`, `.sds.RFM` |

Module-local Python code is generated by `flatc-wasm@26.1.32`, the same compiler
package used by module builds, with `--python --gen-object-api`, in a fresh
compiler instance per schema. Compiler JS SHA-256 and SDK package version are
recorded. The current SDK and SGP4's legacy schema both define
`orbpro.propagator.StateVector` with incompatible layouts. They are generated
into separate namespaces; neither is overwritten or silently aliased.

## FFM's request schema

FFM's manifest no longer names `orbpro.ffm.InvokeRequest`; its `invoke` method takes the typed
`$PRW` record (`PRWExecutionRequest`), and the JSON entry point that once backed the old name is
removed from the source. No `orbpro.ffm.InvokeRequest` Python class is invented.

`PropagatorTrajectorySegments_generated.h` also has no corresponding source in
this checkout; its additional FFM trajectory methods are not claimed as Python
wrappers here. No generated C++ file is reverse-engineered into a new schema.

## Generator checks

All vendored modules are imported by `test_vendoring.py`; generated hashes and
the source manifest hash are verified, and RFM's cross-module union plus the
legacy SGP4 NumPy request are round-tripped. A genuinely absent imported symbol
must be recorded here and in `dependencies.md` with an expected-failure test;
missing imports are never silently skipped. Required inline struct values still
must be supplied to generated object constructors before packing.

## Distribution notices

The immutable SDS `package.json` and README license section declare Apache-2.0;
that revision does not include an SDS LICENSE or NOTICE file. The vendoring
script verifies the declared license and supplies the standard Apache-2.0 text
under `sds/LICENSE.txt`, copied from the installed FlatBuffers package and pinned
by SHA-256. `sds/NOTICE.txt` identifies the exact SDS source and import rewriting.
SDK-derived bindings include the SDK's complete LICENSE with its existing
copyright statement under `invoke/SDK-LICENSE.txt`; `invoke/NOTICE.txt` separates
those from schemas originating in the modules repository. All four notice/license
outputs and both license inputs have recorded SHA-256 hashes. Generated comments
are preserved. These files must be included in the wheel and source distribution.
