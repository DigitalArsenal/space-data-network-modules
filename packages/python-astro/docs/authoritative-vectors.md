# Existing authoritative vectors for a future Python runtime

This is an inventory of existing expected values at modules baseline `283026f`.
It is **not Python numerical verification, measured Python errors, or evidence
of newly passing tests**. Published Python dependencies block the requested
runtime and SDS wrappers; the present package distributes artifacts only.
No expected output below was generated by the Python package.

Paths and commands below are relative to the modules repository root. Import
the existing fixtures when adding Python runtime tests; inline expectations
need a shared fixture extraction coordinated with the owning module. Preserve
the published provenance and fill the metadata gaps before claiming numerical
conformance. No new SDS schema is proposed here.

## Artifact and fixture limitations

- SGP4's selected test loads `dist/browser/module.wasm` through
  `tests/lib/pivInvokeHelper.mjs`, using legacy `PROP`/PropagatorState payloads
  alongside SDS OMM. It does not establish canonical artifact parity.
- Access's selected test calls `index.js`, which loads `dist/access.mjs` and
  `dist/access-binary.js`, rather than `dist/isomorphic/module.wasm`.
- Conjunction's SOCRATES test uses the recovery artifact
  `dist/isomorphic-singlethread/module.wasm`; the primary artifact is pthread
  enabled. Its references can be reused, but its runtime is a different surface.
- Estimation's local numerical JS entry compiles and runs C++; the other local
  JS suite validates recorded evidence against the artifact SHA. Neither is a
  local numerical WASM test.
- HPOP's imported SDK `STANDALONE_RUNTIME_KINDS` covers browser and WasmEdge;
  that loop alone does not establish container WasmEdge coverage.
- Only HPOP and conjunction below have directly reusable JSON expectations.
  Other selected values are inline JS or C++, not exported fixtures.

## 1. SGP4: Vallado radius

**Test:** `propagator/sgp4/tests/tudat_wasm_derived.test.mjs`,
`tudat vallado sgp4 benchmark stays within textbook tolerance`.

**Source:** [pinned Tudat testSpice.cpp](https://github.com/DigitalArsenal/tudat-wasm/blob/c998d24001af69e60f07cc6a29ddf64c422dd9de/tests/wasm/src/testSpice.cpp);
the comments identify the matching Vallado verification case in vendored
`src/cpp/deps/sgp4/SGP4-VER.TLE`.

Inline OMM input: NORAD 5; epoch `2000-06-27T18:50:19.733568`;
mean motion `10.82419157 rev/day`; eccentricity `0.1859667`; inclination
`34.2682 deg`; RAAN `348.7242 deg`; argument of pericenter `331.7664 deg`;
mean anomaly `19.3264 deg`; BSTAR `0.000028098`; mean-motion derivatives
`0.00000023` and `0`. Target JD `2451726.28495062` is three days after epoch.

Expected radius is the norm of published TEME position
`[-9060.4737357, 4658.70952502, 813.686731533] km`, converted to metres.
Absolute radius error must be `<0.01 m`. Returned ECEF speed is only bounded
between `3000` and `8000 m/s`. The test explains that orthonormal rotation
preserves radius while Earth rotation changes velocity. This is a radius
comparison, not full-state accuracy. The introduction says TEME output while
the assertion comments say ECEF; the epoch time scale is not explicit.

```sh
node --test propagator/sgp4/tests/tudat_wasm_derived.test.mjs
```

## Compatibility entry-point differences

`tests/sdk_compat.test.mjs` exists for SGP4, HPOP, conjunction, time and frames.
Lambert uses `tests/sdk-compat.test.mjs`. Access's `test:sdk-compat` script runs
`test/manifestContract.test.mjs`. Estimation and events have no compatibility
test file under either naming convention. These differences must remain
explicit when reporting which existing checks ran.
