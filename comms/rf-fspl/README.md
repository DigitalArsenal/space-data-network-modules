# rf-fspl

Free-space path loss WASM module — Friis (1946) and ITU-R P.525-4 §6.1.

The first module of the `comms/` family. Decomposes a slice of OrbPro's
5,600-line `RfCommsCore.js` JavaScript monolith into modular C++ kernels per
the parent repo's `RF_AUDIT_SOURCES.md` (Section 1).

## Authority

ITU-R P.525-4 §6.1 (free-space attenuation), Friis IRE Proc. May 1946.

Closed-form constant: `32.44778322188337 = 20·log10(4π·1e9/c)`. Both forms
are mathematically identical; both are exposed:

```text
rf_fspl_friis_db(range_m, frequency_hz)
  => 20·log10(4π·R·f/c)

rf_fspl_itu_p525_db(distance_km, frequency_mhz)
  => 32.44778322188337 + 20·log10(d_km) + 20·log10(f_MHz)
```

## Why a "fast path" rather than stream-invoke

Per `space-data-module-sdk`, primitive functions with `(double, double) -> double`
signatures bypass the FlatBuffer stream-invoke envelope. The cost of
encoding a request and decoding a response would dominate the math by 100×
or more for a per-fragment FSPL call. The JS wrapper calls `module._rf_fspl_friis_db`
directly. The manifest still declares port schemas — this is required by
the SDK's contract and lets future stream-based composition work without
breaking the `direct` invoke surface.
