# Streaming Ephemeris-to-OD Implementation Plan

> **For Codex:** REQUIRED SKILL: Use `superpowers:test-driven-development` to
> execute this plan task by task. Use `superpowers:verification-before-completion`
> before marking any task complete.

**Goal:** Replace the Starlink whole-catalog raw-file spool with a bounded
complete-file fetch-to-OD pipeline, persist only OMM/OCM and compact
acknowledged restart state, remove OBD, and prove the exact signed WASM flow can
meet the one-hour WasmEdge target.

**Architecture:** Keep timer, providers, OD, FlatSQL, publication, and status
as independently signed WASM nodes. Starlink freezes a deterministic catalog
plan, fetches a bounded window, and emits each validated complete ephemeris
directly to OD. OD fits bounded batches and gives each source ephemeris a
deterministic transaction identity. FlatSQL acknowledges that identity after
an idempotent OMM/OCM transaction; a bounded graph feedback edge returns the
acknowledgement to Starlink, which persists only the plan identity and highest
contiguous acknowledged position.

**Tech Stack:** C++20/WASI WASM node implementations, SDS FlatBuffers
(`FSB`/`FSO`) with paired canonical and aligned representations, Node.js test
harnesses, the Space Data Module SDK flow compiler, browser WebAssembly, and
WasmEdge.

**Scope:** Only `flows/supplemental-omm/**`. No Go, generic host JavaScript,
SDK, SDS, branch/worktree, stack pin, or unrelated dirty-file edit.

Unless a command includes an explicit `cd`, run it from
`repos/main-packages/space-data-network-modules/flows/supplemental-omm`.
